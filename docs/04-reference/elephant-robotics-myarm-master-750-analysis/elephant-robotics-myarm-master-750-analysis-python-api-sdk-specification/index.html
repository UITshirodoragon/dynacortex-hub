Hiện trạng Python SDK và firmware API của MyArm Master 750

Trang này phản ánh source pymycobot liên quan đến M750: MyArmM, MyArmMControl, protocol/serial, bảng validation và các điểm không thống nhất với docs. Không đánh giá theo mong muốn kiến trúc; chỉ ghi nhận hiện trạng kỹ thuật.

Important

Đính chính hiện trạng thực nghiệm của dự án: Coordinate firmware hiện đã được nhà sản xuất công bố trên app myStudio; người dùng đã burn firmware coord mới nhất vào 3 bộ M750 và quan sát baudrate có thể truyền lên \(1{,}000{,}000~\mathrm{bit/s}\). Trong source pymycobot đang xét, MyArmMControl.__init__ vẫn đặt default \(115{,}200~\mathrm{bit/s}\), nên quan sát 1 Mbps được đánh dấu là LOCAL-OBS, không phải giá trị default trong source.

4. Packet, protocol và phép encode đơn vị

Packet không CRC trong nhóm class này có dạng:

\[ \mathbf{p} = [0xFE,0xFE,LEN,CMD,DATA_0,\ldots,DATA_n,0xFA] \tag{1}\]

Angle codec trong common.py:

\[ s_q = \operatorname{int}(100q[^\circ]), \qquad q[^\circ] = \operatorname{round}\left(\frac{s_q}{100},3\right) \tag{2}\]

Coordinate codec:

\[ s_x = \operatorname{int}(10x[\mathrm{mm}]), \qquad x[\mathrm{mm}] = \operatorname{round}\left(\frac{s_x}{10},2\right) \tag{3}\]

Vì vậy vector Cartesian user-level của write_coords có đơn vị hỗn hợp:

\[ \mathbf{x}_{coord} = [x,y,z,r_x,r_y,r_z]^\top, \quad x,y,z~[\mathrm{mm}], \quad r_x,r_y,r_z~[^\circ] \tag{4}\]

Dạng chuẩn hóa cho phân tích ngoài firmware:

\[ \tilde{\mathbf{x}}_{coord} = [10^{-3}x,10^{-3}y,10^{-3}z,\frac{\pi}{180}r_x,\frac{\pi}{180}r_y,\frac{\pi}{180}r_z]^\top \tag{5}\]

Hai class dùng chung nhiều ProtocolCode, nhưng không tương đương ở cấp API vì khác tên wrapper, default baudrate, bảng robot_limit, số joint trong joint_id, và reply behavior.

7. Reply behavior

Trong MyArmM, set_joints_angle() gọi:

return self._mesg(ProtocolCode.SEND_ANGLES, angles, speed)

Không có has_reply=True. Trong MyArmMControl, MyArmMProcessor._mesg() ép:

kwargs["has_reply"] = True
self._write(real_command)
with self.lock:
    return self._read_genre_result(genre)

Mô hình tương ứng:

\[ \mathrm{MyArmMControl}: \mathrm{write}(\mathbf{p}_{cmd}) \rightarrow \mathrm{read}(\mathbf{p}_{reply}) \tag{6}\]

\[ \mathrm{MyArmM}: \mathrm{write}(\mathbf{p}_{cmd}) \rightarrow \varnothing \quad \text{với nhiều lệnh write} \tag{7}\]

Đây là cơ sở source-level cho nhận định: nạp coord firmware rồi gọi MyArmM có thể chạy một số command overlap, nhưng wrapper không tương đương và không được source chứng minh là an toàn tuyệt đối.

Không có đủ dữ liệu trong source để suy ra ánh xạ tuyến tính toàn cục \(q_i = a_i e_i + b_i\) vì offset, gear, zero calibration và mapping servo-joint không được mô tả đủ trong các file đang xét.

10. Coord firmware blackbox ở mức source Python

Source Python MyArmMControl.write_coords() chỉ encode và gửi packet:

coord_list = []
for idx in range(3):
    coord_list.append(self._coord2int(coords[idx]))
for angle in coords[3:]:
    coord_list.append(self._angle2int(angle))
return self._mesg(ProtocolCode.SEND_COORDS, coord_list, speed, mode)

Các khối IK / frame transform / trajectory / queue không xuất hiện trong source Python. Vì vậy khi write_coords() thành công hoặc thất bại, source Python không cung cấp lý do hình học đầy đủ như joint-limit, singularity, branch IK, orientation conflict hoặc path planner reject.

11. Câu hỏi: burn coord firmware rồi chạy MyArmM được không?

Source cho thấy có overlap protocol, nhất là SEND_ANGLES = 0x22 và GET_ANGLES = 0x20. Vì vậy một số lệnh MyArmM có thể tương tác được với firmware đang hỗ trợ cùng protocol. Nhưng source cũng cho thấy các rủi ro khách quan: khác reply behavior, khác bảng robot_limit, khác surface API, và MyArmM không expose Cartesian API write_coords().

Kết luận trạng thái là: protocol có phần chung, nhưng wrapper không tương đương. Nếu robot đang chạy coord firmware và cần phản ánh đúng Coordinate API hiện tại trong source, class khớp source là MyArmMControl, truyền baudrate explicit khi dùng 1 Mbps.
