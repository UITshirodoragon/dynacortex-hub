03. Tổ chức docs module và project repo

03.1. Quyết định chính của v0.0.3

Bản v0.0.3 tiếp tục là bản docs-only. Zip phát hành trong giai đoạn này chỉ chứa phần tài liệu QMD và skills để port vào Quarto site hoặc knowledge hub hiện có.

Điểm sửa quan trọng so với v0.0.2 là tách rõ hai khái niệm:

Khái niệm Ý nghĩa Có trong zip v0.0.3?
Docs module Gói tài liệu QMD nằm trong 01-system-foundations/myarm_m750_controller_framework/. Đây là thứ đang được đóng zip để import vào hệ thống docs. Có
Project repo Repo triển khai phần mềm thật gồm ROS 2 workspace, Python SDK, config, tools, plugins, benchmark, scripts, tests, docs và skills. Đây là cấu trúc mục tiêu để coding sau này. Không
ImportantPhạm vi của zip v0.0.3

Zip v0.0.3 không phải ROS 2 workspace và không phải skeleton project. Nó chỉ là docs module. Tuy nhiên, trang này vẫn mô tả cấu trúc project repo mục tiêu để developer hoặc AI coding agent có cơ sở tạo skeleton ở bước sau.

03.3. Vai trò của từng nhóm tài liệu trong docs module

Mục Vai trò
index.qmd Trang entry point cho toàn bộ tài liệu framework.
00-overview/ Tổng quan dự án, hardware setup, OS/runtime và mục tiêu control-stack.
01-requirements/ Yêu cầu chức năng, phi chức năng, benchmark count, non-goals.
02-architecture-principles/ Nguyên tắc kiến trúc lai: layered, hexagonal/ports-adapters, plugin architecture, clean boundary.
03-repo-and-docs-organization/ Phân biệt docs module và project repo; quy tắc port, Git, release, AI agent.
04-domain-model-ports-and-adapters/ Domain model, ports, adapters, plugin registry và application boundary.
05-kinematics-planning-and-controller/ FK/IK/Jacobian/planning/controller position-only.
06-hardware-port-and-observation/ HardwarePort tổng hợp actuator, camera, encoder, firmware status, fake/replay/sim adapters.
07-ros2-nonros-runtime-and-network/ ROS 2 DDS path, non-ROS WebSocket/gRPC/ZMQ path, host Jetson/PC.
08-config-system/ Config ngoài code, chia theo tầng Application → Runtime → Core SDK → Port → Adapter → Firmware/Hardware.
09-testing-debug-visualize-benchmark/ Unit/integration/hardware tests, logging, visualization, watchdog, benchmark T1–T4.
10-simulation-digital-twin/ Gazebo, MuJoCo, fake observation, replay và sim/real switching.
11-ai-agent-coding-and-maintenance/ Quy tắc AI coding agent, clean code/comment, maintenance workflow.
12-versioning-and-changelog/ Quy tắc versioning và changelog.
skills/ Skill hướng dẫn sửa docs/code; dùng được cả trong docs repo và project repo.

03.6. Mapping project repo theo tầng kiến trúc

Cấu trúc project repo phải phản ánh dependency direction. Không để application gọi raw firmware API trực tiếp trong production path.

Application
  -> Runtime
  -> Core SDK
  -> Ports
  -> Adapters
  -> Firmware/Hardware

Mapping đề xuất:

Tầng Thư mục chính Trách nhiệm
Application src/myarm_m750_tools/, scripts/, app bên ngoài repo GUI, benchmark runner, task runtime, policy runtime, teleop, experiment scripts.
Runtime src/myarm_m750_bringup/, launch/, config/runtime/ Chọn profile chạy: real, fake, replay, sim, ROS 2, non-ROS, debug.
Core SDK src/myarm_m750_sdk/ Domain model, frame/transform API, FK/IK request/result, planner/controller interfaces, state machine, command arbitration.
Ports src/myarm_m750_sdk/ports/, config/ports/ Contract cho kinematics, planner, controller, hardware, logger, visualizer, benchmark metric.
Adapters plugins/, src/*_driver, src/*_ros2_control, tools/* Pinocchio, MoveIt2, pymycobot, fake/replay/sim, camera, AprilTag/Aruco, OpenCV, visualizer.
Firmware/Hardware config/firmware_hardware/, adapter implementation MyArm M750, firmware coordinate/shake, serial USB, camera Logitech C922, Jetson, Host PC.
Note

src/ đồng thời là thư mục chuẩn của ROS 2 workspace. Các package ROS 2 nằm trong src/, nhưng Python Core SDK vẫn phải có entry point để chạy độc lập khi không source ROS 2 workspace.

03.7. Cấu trúc docs/ trong project repo

Trong project repo thật, docs nên nằm trong:

myarm_m750_controller_framework/docs/
└── 01-system-foundations/
    └── myarm_m750_controller_framework/

Lý do:

  1. Repo chính không bị lẫn source code với docs module.
  2. Dễ port docs module từ zip v0.0.3 vào project repo bằng copy thư mục.
  3. Dễ dùng Quarto riêng cho project repo nếu sau này muốn render docs độc lập.
  4. AI agent có thể đọc docs/ và skills/ trước khi sửa code.

Nếu project repo có Quarto riêng, _quarto.yml nên nằm tại:

myarm_m750_controller_framework/docs/_quarto.yml

hoặc root repo nếu muốn render toàn bộ docs từ root. Quyết định này sẽ chốt khi tạo skeleton project thật.

03.9. Cấu trúc src/ trong project repo

src/ là ROS 2 workspace source folder. Mỗi package phải có trách nhiệm rõ:

Package Vai trò
myarm_m750_sdk Python Core SDK, chạy được độc lập không cần ROS 2.
myarm_m750_description URDF/Xacro/Mesh/SRDF/MoveIt robot model source.
myarm_m750_msgs Custom messages/services/actions nếu cần.
myarm_m750_driver ROS 2 driver node bọc Core SDK và HardwarePort.
myarm_m750_bringup Launch/config composition cho Jetson/Host/sim.
myarm_m750_moveit_config MoveIt2 config, planning group, kinematics plugin config.
myarm_m750_ros2_control ros2_control SystemInterface/controller config ở phase sau.
myarm_m750_benchmarks Benchmark runner, test case generator, metrics exporter.
myarm_m750_tools CLI/tool hỗ trợ calibration, visualization, report, replay.

Không nhồi tất cả vào một ROS 2 node. ROS 2 node nên compose logic từ Core SDK; không tự chứa toàn bộ serial, IK, FK, retry policy, benchmark, visualization.

03.13. Quy tắc không nhầm giữa docs-only và project skeleton

Quy tắc đặt tên artifact:

myarm_m750_controller_framework_vX_Y_Z.zip

Nếu artifact là docs-only, nội dung zip chỉ nên có:

01-system-foundations/myarm_m750_controller_framework/

Nếu artifact là project skeleton hoặc source repo, nội dung zip phải có root:

myarm_m750_controller_framework/

và trong đó mới có docs/, src/, config/, requirements/, tools/, plugins/, .agents/.

Important

Trong v0.0.3, artifact vẫn là docs-only. Cấu trúc project repo trong trang này là tài liệu thiết kế, chưa phải file/folder thực sự trong zip.
